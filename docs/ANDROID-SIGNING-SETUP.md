# نظام التوقيع الثابت — Hardware Inspector Pro

## الحالة
**الإصدار 0.2.3 هو أول إصدار مخصص للتوقيع الدائم.** لا تنشر APK من CI (Debug) على أنه إصدار تحديث. لا يتم إصدار APK رسمي إلا من مهمة `Publish Stable Signed Android APK`، وبعد التحقق من شهادة التوقيع.

بصمة شهادة التوقيع العامة SHA-256 محفوظة في `app/signing-certificate.sha256`. الملف آمن للنشر ولا يحتوي على مفتاح خاص.

## إعداد لمرة واحدة على GitHub

1. حمّل الأرشيف الخاص `HardwareInspectorPro-signing-PRIVATE-v1.zip` الذي سُلّم لصاحب المستودع **خارج GitHub**. فك الضغط محليًا على الهاتف أو الحاسوب. **لا ترفع الأرشيف أو المفتاح أو كلمة المرور إلى المستودع العام أو إلى Issue/PR.**
2. افتح https://github.com/scientifica007/HardwareInspectorPro/settings/secrets/actions بعد تسجيل الدخول إلى حسابك.
3. اختر **New repository secret**، وسمِّه `HIP_KEYSTORE_B64`. انسخ **المحتوى الكامل** لملف `1-HIP_KEYSTORE_B64.txt` إلى الحقل Value. اضغط **Add secret**.
4. أنشئ سرًا ثانيًا اسمه `HIP_KEYSTORE_PASSWORD`، وقيمته المحتوى الكامل لملف `2-HIP_KEYSTORE_PASSWORD.txt`. احفظه.
5. افتح https://github.com/scientifica007/HardwareInspectorPro/actions/workflows/android-stable-release.yml واختر **Run workflow** على فرع `main`. (إذا لم يظهر الزر، تأكد من تفعيل GitHub Actions والصلاحيات.)
6. بعد نجاح مهمة `sign-and-publish`، افتح https://github.com/scientifica007/HardwareInspectorPro/releases/latest ثم حمّل `HardwareInspectorPro-v0.2.3.apk` وليس Debug APK.
7. احتفظ بالأرشيف الأصلي في نسختين آمنتين. فقدان مفتاح التوقيع يمنع إصدار تحديثات على نفس التطبيق دون اضطرار المستخدمين إلى إعادة التثبيت.

تتحقق المهمة آليًا من: وجود السرَّين، وصحة PKCS12، وتطابق الشهادة مع البصمة الثابتة، ووجود توقيع APK v2 صالح، ثم تنشر نسخة واحدة بإصدار غير مكرر. عند أي فشل لا ينشر APK.

## الانتقال من الإصدار السابق 0.2.2

**أول انتقال فقط:** نسخة v0.2.2 بُنيت بمفتاح Debug متغير، لذا لا يمكن للنظام تثبيت v0.2.3 الموقّع بالمفتاح الثابت فوقها. يتطلب الانتقال إزالة v0.2.2، ولو كانت بياناتك مهمة.

1. افتح v0.2.2، أوقف المراقبة، وحدّث القراءات واحفظ تقرير JSON.
2. تأكد من وجود الملف في مدير الملفات قبل إزالة التطبيق.
3. أزل v0.2.2.
4. ثبّت ملف APK الرسمي v0.2.3 من صفحة Releases.
5. فور فتحه، **قبل بدء أي مراقبة جديدة**، اختر «استرجاع عدادات المراقبة من تقرير JSON محفوظ» واختر التقرير الذي حفظته. أكّد الاسترجاع.
6. من v0.2.3 فصاعدًا، ينبغي أن تعمل تحديثات الإصدار التالي في المكان نفسه، دون إزالة، بشرط تطابق الشهادة وحزمة التطبيق وزيادة versionCode.

**تنبيه:** الاسترجاع ينقل بيانات المراقبة الموجودة في JSON، ولا يعيد ما لم يُسجّل أصلًا، ولا يعيد تلقائيًا أذونات النظام أو إعدادات تثبيت التطبيق. احفظ التقارير المستقبلية دوريًا.

## الممارسات الأمنية
- **ممنوع نشر PKCS12 أو base64 أو كلمة المرور في Git أو Logs.**
- يمكن نشر بصمة شهادة التوقيع العامة فقط.
- GitHub Secrets مشفرة داخل المنصة؛ قيمة السر لا تُقرأ من واجهة GitHub بعد حفظه.
- لا تعيد توليد المفتاح لأي إصدار لاحق، وإلا سيتكرر فشل التحديث.
- لا يمكن لاتصال ChatGPT الحالي ضبط الأسرار نيابة عن المستخدم؛ إعداد السرَّين أعلاه يتطلب إجراءً مباشرًا من مالك المستودع.

## الاختبار
- عند كل Pull Request أو تحديث للفرع الرئيسي، تشغّل مهمة CI ترجمة Debug ثم Release بمفتاح اختبار عابر **لا يُنشر**. هذا للتحقق من سلامة الشيفرة والتوقيع في Gradle فقط.
- النشر الحقيقي لا يبدأ إلا من **Publish Stable Signed Android APK** يدويًا، باستخدام السرّين الحقيقيين.
- يمكن مقارنة البصمة المنشورة بشهادة APK باستخدام Android `apksigner verify --print-certs`.
