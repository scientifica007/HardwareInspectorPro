# HardwareInspectorPro

تطبيق Android أصلي (Java / Android SDK) لفحص مكونات الهاتف، مع إعطاء الأولوية لهاتف **OPPO A12** الذي صدر أصلًا بنظام Android 9.

## البناء والتثبيت والتحديث

- **الإصدارات الموقّعة الثابتة فقط:** [صفحة Releases](https://github.com/scientifica007/HardwareInspectorPro/releases). ملف `HardwareInspectorPro-v*.apk` المنشور بواسطة مهمة **Publish Stable Signed Android APK** هو ملف التثبيت المعتمد.
- لا تثبّت ملفات `app-debug.apk` كتحديثات مستقرة؛ مفاتيح Debug متغيرة. لم تعد مهمة التحقق الآلي تنشر ملفات APK للاستخدام الميداني.
- يتطلب نشر أول ملف موقّع تفعيل سرَّي GitHub مرة واحدة. اتبع [دليل إعداد التوقيع الدائم](docs/ANDROID-SIGNING-SETUP.md).
- **الانتقال من v0.2.2 إلى v0.2.3:** احفظ تقرير JSON، ثم أزل نسخة Debug القديمة إن رُفض تثبيت الجديدة، وثبّت APK الموقّع، واسترجع السجل قبل بدء المراقبة. بعد هذا الانتقال، يمكن للتحديثات الموقّعة بالمفتاح نفسه أن تتم دون إزالة التطبيق.

> حالة الإصدار: v0.2.3 جاهز للبناء الموقّع بعد ضبط أسرار GitHub، وليس ملفًا منشورًا للتنزيل بعد. واجهة البوصلة والجيروسكوب والمراقبة التراكمية اختُبرت وظيفيًا ميدانيًا على هاتف OPPO A12؛ نظام التوقيع الثابت لم يُختبر كتحديث متتابع بعد.

## ما الذي يقرأه؟
- طراز الجهاز وإصدار النظام واللوحة والمنصة والذاكرة RAM وقسم التخزين.
- معلومات المعالج المتاحة من Android وملفات النظام المسموح بقراءتها، ومعلومات OpenGL GPU إن أمكن.
- حرارة البطارية والجهد والشحن والحالة والتيار والعدادات التي يوفرها المصنع.
- الشاشة وكثافة البكسل والكاميرات ومستشعرات الحركة والمجال المغناطيسي والقرب والإضاءة.
- Wi-Fi، الاتصالات، Bluetooth، NFC، الأجهزة المتصلة عبر USB.
- اختبارات أصلية اختيارية للاهتزاز والصوت والميكروفون والمستشعرات وGPS واللمس.
- تصدير التقرير JSON محليًا دون اتصال بخادم.

## العمر والأزمنة: تفسير بالغ الأهمية
- `elapsedRealtime()`: مدة منذ **آخر إقلاع** وتشمل النوم، وليست ساعات عمر الهاتف.
- `uptimeMillis()`: مدة استيقاظ النظام منذ الإقلاع، وليست ساعات استخدام المعالج طوال حياته.
- تاريخ أول استعمال: **لا يُطلب إدخاله يدويًا**؛ التطبيق يحتفظ بتاريخ أول رصد ويبيّن أن تاريخ تصنيع الجهاز غير متاح بشكل موثوق.
- سجل المراقبة الاختياري: يجمع **مدة تشغيل المراقب**، والوقت الذي كانت فيه الشاشة مضاءة، والوقت الذي كانت فيه البطارية قيد الشحن **منذ بدء استعمال هذا التطبيق فقط**. لا يتضمن أي وقت سابق. التسجيل يحتاج تشغيل خدمة ظاهرة بإشعار، وقد تحد بعض إعدادات توفير الطاقة من استمراريتها.
- عدد دورات البطارية الرسمي متاح من API 34 إذا وفّره النظام. هو غالبًا غير متاح في Android 9. لا نخترع قيمة بديلة.
- لا يوجد API عامة موثوقة لإجمالي ساعات CPU/GPU/Flash/Screen/Camera منذ تصنيع الهاتف. تُعرض هذه الحقول بوضوح بوصفها غير متاحة.

## الخصوصية
لا يتضمن التطبيق خدمة شبكة أو SDK للإعلانات أو التحليلات. أذونات الموقع والميكروفون تُطلب عند تشغيل الاختبارات فقط. لا تُحاول قراءة IMEI أو الرقم التسلسلي المقيد أو غيره من المعرّفات الحساسة. جميع التقارير تُنشأ محليًا.

## أصل التصميم
يستلهم الوظائف العامة من ملف HTML المقدم `phone_hardware_monitor_v2.html` دون أن يضمه داخل WebView. تم تصحيح الخلط بين مقدار التخزين المتاح للمتصفح والتخزين الفعلي، وبين DPR ودقة اللوحة الحقيقية، وبين dBFS وdB SPL، وبين واجهة Bluetooth في المتصفح ودعم الشريحة، وبين حرارة البطارية والحرارة الداخلية للمعالج.

## الإصدار v0.2.0: تجربة OPPO A12
تم تحديث هذا الإصدار بناءً على تقرير فحص فعلي لهاتف OPPO CPH2083/Android 9:
- **أزيلت حقول إدخال تاريخ أول الاستعمال يدويًا**. يكتفي التقرير بتسجيل أول رصد فعلي بواسطة التطبيق، وساعات آخر إقلاع والنظام المستيقظ.
- **بوصلة حية Android Native**: استخدام مقياس التسارع BMA253 والحقل المغناطيسي AKM00918 لحساب السمت تجاه الشمال المغناطيسي بواسطة SensorManager.getRotationMatrix() وgetOrientation(). تتأثر النتيجة بالمعادن ومجال الشحن.
- **جيروسكوب حي**: سرعات دوران X/Y/Z بالدرجة/الثانية. يعلن هاتف OPPO المختبر عن المورد `virtual_gyro` ولذلك ينبه التطبيق إلى أنه افتراضي، ولا يزعم وجود شريحة جيروسكوب مستقلة.
- **اهتراء وحدة التخزين eMMC**: محاولات قراءة `life_time` و`pre_eol_info` عبر sysfs للقراءة فقط. تشرح النتائج نطاقات الاستهلاك المقدّرة. إذا منع نظام Android القراءة تُعرض «غير متاح»، ولا تُخترع قيمة.
- **عدادات I/O لقسم eMMC** (عندما تتاح): كميات القراءة والكتابة وزمن انشغال I/O منذ تهيئة عدادات النواة؛ ليست ساعات عمل منذ شراء الهاتف.
- **عداد الخطوات** (إذا سمحت الأذونات): منذ آخر إقلاع وليس طوال عمر الهاتف.

لا تُجري أي عمليات root أو أوامر shell للتغيير. بدون Root/امتيازات الشركة قد لا تتاح معلومات الاهتراء على ColorOS.

[وثائق Android الخاصة باتجاه البوصلة](https://developer.android.com/develop/sensors-and-location/sensors/sensors_position) و[مصدر Android المفتوح لعدادات eMMC](https://android.googlesource.com/platform/packages/services/Car/+/master/service/src/com/android/car/storagemonitoring/EMmcWearInformationProvider.java).

## v0.2.1: زيادة فحص عمر البطارية
- عندما تسمح نواة Android/ColorOS، يقرأ التطبيق `/sys/class/power_supply/battery/cycle_count` لعرض عدد دورات الشحن المُبلّغ عنها؛ قد يكون محجوبًا على Android 9.
- يحاول أيضًا قراءة `charge_full` و`charge_full_design` واحتساب نسبة السعة الحالية إلى التصميم **فقط إذا كان العدّادان متسقين**؛ هي مؤشر يبلّغ عنه السائق وليست معايرة فعلية دقيقة لصحة البطارية.
- لا يعني الصفر في عداد الدورات أن البطارية جديدة، ولا يدل غياب البيانات على تلفها.
- تفاصيل مرجعية: [وثائق sysfs لبطارية Linux](https://android.googlesource.com/kernel/common/+/android-mainline/Documentation/ABI/testing/sysfs-class-power).


## v0.2.2 — سجل أحداث المراقبة بالثواني

- **سجل محلي** يحتفظ بأحدث 300 حدث؛ كل حدث يتضمن التاريخ والساعة حتى الثانية، ومصدر الحدث وحالة الشاشة والشحن.
- يسجل بدء المراقبة، إيقافها عبر الزر/الإشعار، إضاءة وإطفاء الشاشة، وبدء/انتهاء الشحن.
- الحالات المبدئية عند بدء الجلسة موسومة `initial_state`، فلا تختلط مع أحداث الانتقال الفعلية.
- مدة المراقبة تستند إلى `SystemClock.elapsedRealtime()` وتُحتسب بالثواني (بما فيها النوم العميق أثناء استمرار الخدمة).
- عندما يتأخر تحديث المراقبة أكثر من 120 ثانية، تُحتسب مدة الجلسة، لكن المدة التي لا يمكن تأكيد حالة الشاشة/الشحن خلالها تُضاف إلى **الفترات غير المؤكدة** ولا تُنسب إلى تشغيل الشاشة أو الشحن.
- إذا بدأت جلسة جديدة بعد جلسة قديمة لم يُسجّل إغلاقها، يُضاف `previous_session_unresolved`، ولا تُخترع أحداث أو ساعات تشغيل سابقة.
- تُضمّ الأحداث والعدادات إلى `monitoring.events` في تقرير JSON الجديد (`HardwareInspectorPro-v2`).
- **استعادة اختيارية من JSON:** لأن APK التجريبي قد يحمل توقيعًا مختلفًا، احفظ تقرير JSON من الإصدار السابق قبل إزالة تثبيته. بعد تثبيت v0.2.2، اختر **استرجاع عدادات المراقبة من تقرير JSON محفوظ** قبل تشغيل المراقبة. تُسترجع المجاميع المقاسة، وعند الاستعادة من v0.2.1 تكون الدقائق تقريبية ولا تُستعاد أحداث لم تُسجل أصلًا. الاستعادة مقيدة بهاتف مطابق وبسجل محلي فارغ لمنع دمج تقارير مكررة.
- تم تعديل قراءة Wi-Fi حتى لا يُظهر بيانات SSID أو قيم -1 التالفة عندما تكون الواجهة معطلة أو غير متصلة.

**حدود الدقة:** هذا سجل مشاهدة أحداث، لا ضمان بتشغيل الخدمة إذا أنهى Android أو ColorOS عملية التطبيق قسريًا. تغيّر الساعة قد يغيّر أوقات الأحداث الجداريّة؛ قياس الفترات يستخدم ساعة monotonic. يجب اختبار رصد الخلفية على OPPO A12 ميدانيًا.

**مشكلة توقيع نسخ Debug:** لا يمكن تثبيت نسخة ذات توقيع مختلف فوق السابقة. من غير الآمن نشر مفاتيح توقيع خاصة داخل المستودع العام. يلزم إعداد مفتاح توقيع ثابت ومحفوظ سرًا في بيئة البناء للإصدارات المقبلة. استيراد JSON هو حل انتقالي للمراقبة، وليس بديلًا دائمًا لإدارة توقيع الإصدار.
